# CHASS ideas backlog

Source: the mega review of 2026-10-29 (two idea agents read the whole app). Tick a box when an idea ships.
Effort: S is under a day, M is a few days, L is a week or more. All art and audio must stay original or placeholder.

## Do next: high impact, small or medium effort

- [x] **Random variant roulette per game ('Chaos Dice')** (impact: high, effort: S, game modes)

- [ ] **New variant: Kamikaze Pawns (explosive captures)** (impact: high, effort: M, variants)

- [ ] **Share-link rooms and accounts-free play** (impact: high, effort: M, multiplayer)
  - Why: The lowest-friction way to play a friend is a link. No signup means no password storage, no GDPR account surface, and a faster path to first game.

Risks: tokens in localStorage are lost on cleared data, so offer a recovery link; rooms need TTL cleanup; display names need length limits and basic profanity or HTML escaping since they render in the UI.

- [ ] **PGN export/import with variant headers, plus replay viewer** (impact: high, effort: M, replay)
  - Why: There is no way to save or share a game. san.ts and MoveRecord already produce SAN, and Game stores startFen and seed, but nothing serializes them. Replays are also the cheapest shareable content for a meme game.
  - How: First steps: (1) Add src/engine/pgn.ts (pure) with toPgn(game) and parsePgn(text): headers Variant (use the Lichess/Fairy convention names, e.g. Chess960, plus a custom 'Chass' tag listing variant ids), FEN and SetUp for non-standard starts, and the seed in a custom tag so randomised setups reproduce. (2) Represent duck turns explicitly as a combined token (Fairy-Stockfish uses e2e4,e4a4 per docs/ai-feasibility.md) so one ply equals one move plus duck; tests round-trip against Game for all four variant combos. (3) Add Download/Paste PGN buttons and a replay mode in App.tsx that steps a read-only Game with prev/next and keyboard arrows, replaying cinematics optionally. Risks: standard PGN tools will not understand dragon bishop piece letter D or duck moves, so document this as a Chass dialect; importer must reject illegal SAN with a line number rather than crash; need a hard size cap on pasted text.

- [ ] **Accessibility: keyboard play, screen reader, motion and contrast** (impact: high, effort: M, accessibility)

  - How: First steps: (1) Make Board.tsx a roving-tabindex grid (role=grid, arrow keys move focus, Enter selects and confirms, Escape cancels) with square labels such as 'e4, white knight'. ## Big bets: high impact, large effort

- [ ] **Share: replay export as GIF/WebM clip and permalink to a game** (impact: high, effort: L, share)
  - Why: Funny captures are inherently shareable; the product needs a one-tap way to share them, which also spreads the game.
  - How: Permalink: encode variants + seed + SAN move list (already produced by san.ts and Game.play) into URL hash; loading replays it deterministically (engine is DOM-free and seeded). Clip: use MediaRecorder on a canvas capture of the board area for the last cinematic (3s hard cap already exists: MAX_CINEMATIC_MS), export WebM with a 'Download clip' button on the capture; GIF via a tiny in-house encoder only if WebM is not accepted by targets. Add 'Copy game link' and a text card option ('I got mated by a duck in 23 moves').

- [ ] **Server-authoritative online play on the shared engine** (impact: high, effort: L, multiplayer)
  - Why: The engine is DOM-free and deterministic (Game takes a seed; applyMove and legalMoves are pure), so a small Node server can validate every move. Today useChass.ts owns the clock and the result locally, so nothing can be trusted online.
  - How: First steps: (1) Add a server/ package (Node + ws, or one Cloudflare Durable Object per game) that imports src/engine unchanged, holds one Game per room, accepts only {move uci, duck?, seq}, and broadcasts {seq, uci, serverClockMs}. (2) Define a versioned, schema-validated protocol in src/protocol/ (hello/resume, move, duckPlace, resign, drawOffer, snapshot = startFen + variantIds + seed + move list). Clients render from snapshots, never trust local state. (3) Make the clock server-authoritative: store remaining ms per side plus lastMoveAt, send absolute deadlines, client only interpolates for display; reconnect with a session token that triggers a full snapshot resend. Anti-cheat: reject illegal or out-of-turn moves, rate-limit, never relay aim or hover data; engine-assist cheating has no cheap fix, so declare it out of scope for casual play. Risks: the local clock pauses during cinematics (useChass.ts clock effect uses !cine), which cannot exist online, so cinematics must become cosmetic and non-blocking there. Game seeds with Math.random (game.ts constructor), so the server must issue the seed for Chess960. Hosting and GPL: Fairy-Stockfish is GPL-3 (docs/ai-feasibility.md); keep it server-side only, or keep the own TS minimax and avoid the issue entirely. Cheapest hosting is a single Node container or Durable Objects, since static hosts cannot hold sockets.

- [ ] **New variant: Hot Potato Queen** (impact: medium, effort: M, variants)
  - Why: Adds a funny constant pressure: you never want to hold the queen too long.
  - How: Rule: each side's queen carries a fuse counter. Every move the queen does not make decreases it by one from 6. At zero the queen explodes and is removed. Moving the queen resets the fuse. Needs per-piece auxiliary state in State (a fuse map keyed by square, kept updated on move) and hooks afterMove (decrement/relocate fuse) and a state serialization addition to FEN (extra field) so undo and perft stay consistent. Emits a 'fuse' event for a ticking sfx and a 'queenExploded' event for a cinematic.

- [ ] **New variant: Pawn Rebellion (pawns that refuse)** (impact: medium, effort: M, variants)
  - Why: Pieces with personalities turned into rules. Every game some pawn disobeys and the player laughs at the chaos.
  - How: Rule: when a side has not moved a pawn in 5 plies, a random pawn (seeded rng stored in State) becomes 'union striking' and cannot be moved until that side moves any other pawn. Implement via extraMoves cannot remove moves, so add a new hook filterMoves(state, moves) => Move[] applied in legalMoves in rules.ts. Add 'strike' event and a cinematic with tiny picket-sign sprite and caption 'fair wages for pawns'.

- [ ] **New variant: Teleporting Rooks (portal squares)** (impact: medium, effort: M, variants)
  - Why: Cheap to implement with existing extraMoves and extraAttackers, visually distinct, and good for gags.
  - How: Rule: setupFen chooses two portal squares (via rng) on ranks 3-6; a rook standing on one portal can also move to the other portal and slide from there. Implement in extraMoves (call addTo on the squares reachable from the sibling portal) and mirror in extraAttackers. Portals drawn by Board.tsx from a new optional state field or a variant-provided overlay list (Variant.overlays?(state): Square[]). Add an event 'teleport' with a whoosh sfx.

- [ ] **Synthesized sound pack: per-piece voices and event stingers (original audio only)** (impact: medium, effort: M, sound design)

- [ ] **Analysis board and hint modes using the existing minimax** (impact: medium, effort: M, analysis)
  - Why: src/ai/search.ts already evaluates every variant in a worker with a time limit, but it is only used to pick opponent moves. The same search can power an eval bar, best-move arrow and post-game blunder review at no new dependency cost.
  - How: First steps: (1) Extend ai.worker.ts with an 'analyse' request returning {score, pv, depth} for a state (the Game evaluator hook for blunder events already exists, game.ts GameOptions.evaluator). - [ ] **New variant: Knight Roulette (Chad's horse)** (impact: medium, effort: L, variants)
  - Why: Ties directly to the existing horse and gun gag and creates a lottery moment.
  - How: Rule: each capture by a knight is a gamble. rng.next() < 0.5: capture succeeds as usual; otherwise the knight 'misses' and is removed instead (the victim stays). Needs hook resolveCapture(state, move, rng) => 'normal' | 'backfire' and an rng in State; engine must stay deterministic so the seed is stored in Game. Event 'backfire' triggers gun-any cinematic variant where the hand-gun aims at the attacker. AI: treat knight captures as expected value in search.ts evaluation.

- [ ] **Community and mod content packs with a safety model** (impact: medium, effort: L, content-packs)
  - Why: The product is already data-driven, which makes user packs natural, but loading third-party JSON and media into the page is a trust boundary. I have not verified how sprite and media paths are resolved in CinematicLayer.tsx and MemeOverlay.tsx, so path handling is a risk to audit, not a confirmed bug.
  - How: First steps: (1) Define a pack format (zip or a hosted folder with pack.json: id, version, license, author, contents list) and a loader that reads it into memory and creates object URLs, never writing to or reading from arbitrary paths. (2) Enforce limits in the validator and at runtime: allow SVG only after sanitising (no script, no external href, no foreignObject), cap file sizes and counts, allow only a fixed set of step types (already a closed union in types.ts), clamp durations, and reject any path containing '..' or a scheme. Keep CSP strict (no inline script, img-src data: blob: self) to contain damage.
